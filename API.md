# Fashion Inspo Libraries — API

Everything the site shows is available as static JSON (for other apps and scripts) and as a JavaScript API inside the page (for bookmarklets, extensions and embeds). Mix & Match is built on the same data and engine.

Base URL when hosted on GitHub Pages: `https://cschris-ops.github.io/fashion-inspo-libraries/`

## Static data endpoints

| Path | What it holds |
| --- | --- |
| `data/manifest.json` | Content hash per catalogue, lookboards and wardrobe; poll this to detect updates cheaply. |
| `data/catalogues/<brand>.json` | One brand: seasonal looks, formulas and verified products. |
| `data/lookboards.json` | The shop-the-composition boards (product ids). |
| `data/wardrobe.json` | Every wearable piece, one by one, plus formula/seasonal mappings and match odds. |
| `data/seed.js` | The same catalogues as a script, for `file://` use and first paint. |

All endpoints are regenerated by `scripts/catalogue-pipeline.mjs` whenever catalogue data changes, so hashes in the manifest always match the files.

```jsonc
      "material": "wool", "pattern": null, "formality": 4,
      "seasons": ["spring","fall","winter"], "categories": [],
      "price": { "amount": 149, "currency": "USD", "basis": "reference" },
      "url": "https://…", "image": "assets/item-stone-trouser.jpg", "productId": "md-trouser",
      "sources": [{ "kind": "product", "id": "md-trouser", "title": "Pleated wool-blend trousers" }]
    }
  ],
  "formulas": { "<formula id>": ["<piece id>", "…"] },
  "seasonal": { "<seasonal look id>": ["<piece id>", "…"] },
  "aliases": { "md-trouser": "massimo--pleated-wool-blend-trousers" },
  "odds": { "brands": [ { "brand": "zara", "combinations": 45045, "good": 0.36, "strong": 0.04, "average": 55 } ], "crossover": { "…": 0 } }
}
```

Field notes:

- `colour.source` is `name`, `note`, `look` (read from the formula rule), `product` (verified facts) or `default` (an illustrative colour picked for the garment type because the catalogue names none).
- `price.basis` is `catalogue` (seasonal look price), `reference` (verified product reference) or `estimated` (share of a formula's basket, weighted by slot).
- `formality` runs from 1 (relaxed) to 5 (formal); accessories have `null`.
- `odds` are Monte Carlo estimates with a fixed seed, so they only change when catalogues do.

## In-page JavaScript API

The page exposes `window.FashionLibrary`:

```js
FashionLibrary.catalogues()                 // effective catalogues (synced data + local updates)
FashionLibrary.product('md-suede')          // one verified product
FashionLibrary.sync()                       // revalidate the manifest now
FashionLibrary.updateProduct('zara', 'z-oxford', { price: { amount: 21, currency: 'USD' } }, 'on sale')
FashionLibrary.exportChanges()              // local updates as a fil-changes bundle for data/inbox/
FashionLibrary.on('change', ({ diffs }) => …)
```

### Mix & Match: `FashionLibrary.studio`

```js
const s = FashionLibrary.studio;

s.pieces({ slot: 'shoes', brand: 'zara', season: 'winter' })  // filterable piece list
s.piece('md-loafer')                                            // by piece id, product id or alias
s.equip(['z-navy-blazer', 'massimo--oxford-shirt'])             // dress the avatar
s.remove('outerwear'); s.clear()
s.outfit()                // { pieces, colours, tuck, open, score, label, parts, notes, brands, mode }
s.score(['u-knit', 'md-trouser', 'md-loafer'])                  // score any combination without wearing it
s.suggest({ mode: 'same-brand', brand: 'hm', season: 'fall', count: 3, locked: { top: 'hm--oxford-shirt' } })
s.shuffle({ mode: 'crossover', season: 'summer', seed: 42 })    // weighted random roll (probability ∝ e^(score/6))
s.odds({ season: 'winter', samples: 3000 })                     // same-brand vs crossover odds
s.svg(['u-knit', 'md-trouser'], { viewBox: '40 20 320 960' })   // avatar as an SVG string
s.thumbnail('hm--peacoat')                                      // single-piece SVG
s.on(outfit => console.log(outfit.score))                       // listen to every change
```

Match chance (`score`) combines four parts:

| Part | What it checks |
| --- | --- |
| Colour (34%) | Accent count, palette size, tonal vs contrast, denim on denim, belt/shoe leather match, black + brown |
| Formality (26%) | Spread between the dressiest and most casual piece; blazer + leather sneaker counts as deliberate smart-casual |
| Season (20%) | Whether every piece suits the chosen season; shorts under winter coats, sandals with wool |
| Proportion (20%) | The site's fit rules: long coat over wide trousers, cropped layers over full trousers, tuck + belt, height |

The blend is pulled down by the weakest part and stretched so random combinations average about 50: 80+ is **Strong**, 65+ **Good**, 50+ **Risky**, below 50 **Clash**.

### Engine without the page

`app/wardrobe.js` and `app/avatar.js` also run in Node:

```js
const W = require('./app/wardrobe.js');
const A = require('./app/avatar.js');
const wardrobe = W.build(catalogues);           // catalogues = parsed data/catalogues/*.json
const best = W.suggest(wardrobe, { mode: 'crossover', count: 1 })[0];
const svg = A.render({ slots: best.slots });
```

## Sending updates back

- Product corrections made in the site are queued as `fil-changes` bundles. With `window.FIL_CONFIG = { pushUrl }` they are POSTed there; otherwise export them from the Catalogue updates panel and add the file to `data/inbox/`.
- Supported change ops: `product.patch|upsert|remove`, `formula.patch|upsert|remove`, `seasonal.patch|upsert|remove`, `catalogue.upsert`.
- For push-style live updates, set `FIL_CONFIG.liveUrl` to an EventSource endpoint; any message makes open pages revalidate the manifest.
